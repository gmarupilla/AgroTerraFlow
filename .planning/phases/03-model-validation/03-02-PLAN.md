**Function 1: `_assign_block_ids(lats, lons, n_blocks_side=4)`**
- Use `np.linspace` for lat/lon edges, `np.digitize` for row/col indices
- Return `row_idx * n_blocks_side + col_idx` as block IDs
- Exact implementation from RESEARCH.md Pattern 2

**Function 2: `_spatial_block_cv(lats, lons, labels, n_blocks_side=4, buffer_deg=0.5)`**
- Call `_assign_block_ids` for block assignment
- Count unique blocks: if `< 2`, log warning and return `[]`
- `n_splits = min(n_unique_blocks, 5)`
- Use `GroupKFold(n_splits=n_splits).split(X, labels, groups=block_ids)`
- For each fold: compute `cdist(train_coords, test_coords).min(axis=1)`, keep `train_idx[min_dists > buffer_deg]`
- Skip fold if buffered training set or test set is empty
- TerraFlow has no trainable params — per-fold prediction = labels from config scoring (same deterministic model). For CV purposes, use test labels directly as predictions (since the model is deterministic with fixed params, applying the same config to test cells yields the same labels). Compute `accuracy_score(labels[test_idx], labels[test_idx])` which is always 1.0 per fold — document this explicitly. The scientific value is whether buffer exclusion leaves enough training data and whether spatial blocks produce balanced folds.
- **Actually:** The research notes say "re-score test cells with fixed model_params." Since suitability_score is deterministic, the correct approach for a meaningful CV: use spatial mean of training-fold scores as the test prediction (a spatial baseline). Implement as: `train_mean_label = most common label in buffered training set`, predict all test cells as that label, compute accuracy. This gives non-trivial fold accuracy.
- Return `fold_accuracies` list

**Function 3: `_compute_kappa(cells_df, reference_df)`**
- Build KDTree from `cells_df[['lat','lon']]`
- Query with `reference_df[['lat','lon']]`
- Check max distance: if `> 1.0` degree, emit `warnings.warn(f"Reference points are up to {max_dist:.1f} degrees from nearest cell — possible extent mismatch")`
- Return `cohen_kappa_score(reference_df['label'].values, matched_labels, labels=['low', 'medium', 'high'])`

**Function 4: `_morans_i(lats, lons, residuals)`**
- Exact implementation from RESEARCH.md Pattern 5
- `D = cdist(coords, coords)`, `W = np.exp(-D)`, fill diagonal 0, row-standardize
- Guard: if `(z @ z) == 0 or S0 == 0: return None`
- Return `float((n / S0) * (z @ W_row @ z) / (z @ z))`

**Function 5: `run_validation(config_path: Path) -> Path`**
- Load config via `load_config_dict` + `build_config`
- Raise `ValueError` if `cfg.validation is None`
- Resolve `output_dir`, find latest run dir (most recent `runs/*/features.parquet`)
- Read `features.parquet` into DataFrame
- Extract `lats, lons, labels, scores` from DataFrame columns `lat, lon, label, score`
- Call `_spatial_block_cv(lats, lons, labels, cfg.validation.n_blocks_side, cfg.validation.buffer_deg)`
- Compute `mean_fold_accuracy = float(np.mean(fold_accs)) if fold_accs else None`
- Compute `_morans_i(lats, lons, scores - scores.mean())`
- If `cfg.validation.reference_csv` is not None: load CSV, call `_compute_kappa`, else kappa = None
- Read existing `report.json` from run dir
- Add `report["validation"]` block per RESEARCH.md Pattern 6:
  ```python
  report["validation"] = {

  }
  ```
- Write report.json atomically (read → modify → write to tmp → rename, same as pipeline.py `_atomic_write_text` pattern — copy that helper or use `tempfile.NamedTemporaryFile` + `os.replace`)
