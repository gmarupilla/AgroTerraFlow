**terraflow/cli.py changes:**

Update `sensitivity_cmd` to add proper error handling (matching the `run_cmd` pattern). The current stub from Plan 01 just calls `run_sensitivity(config)` bare. Add try/except to catch `ValueError` (from missing sensitivity section or invalid n_samples) and convert to `SystemExit(1)`:

```python
@app.command("sensitivity")
def sensitivity_cmd(
    config: Annotated[
        Path,
        typer.Option("--config", "-c", exists=True, file_okay=True,
                     dir_okay=False, readable=True, help="Path to YAML config file"),
    ],
) -> None:
    """Run Sobol' and/or Morris sensitivity analysis."""
    from .sensitivity import run_sensitivity
    try:
        report_path = run_sensitivity(config)
        logger.info("Sensitivity analysis complete. Report: %s", report_path)
    except ValueError as e:
        logger.error("Sensitivity analysis configuration error: %s", e)
        print(f"ERROR: {e}", file=sys.stderr)
        raise SystemExit(1)
    except Exception as e:
        logger.error("Sensitivity analysis failed: %s", e, exc_info=True)
        print(f"ERROR: Sensitivity analysis failed - {e}", file=sys.stderr)
        raise SystemExit(1)
```

Note: The power-of-2 validation error comes from Pydantic's `field_validator` on `SensitivityConfig.n_samples` which raises `ValueError` during config loading inside `run_sensitivity()`. This gets caught by the `ValueError` handler and printed as a clear CLI error with exit code 1.
